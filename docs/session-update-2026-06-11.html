"Can we deploy / configure from the browser?" — investigated

You asked whether we could grab the user's access token and run config/deploys from JavaScript. A source-cited feasibility study settled it.

Capability from the browserVerdictWhy
Assign permission sets to the current user RELIABLE @AuraEnabled Apex → PermissionSetAssignment on UserInfo.getUserId(). This is what Run Setup does.
Deploy / publish the AgentScript agent at runtime NOT VIABLE Publishing an AiAuthoringBundle is CLI/Agent-Studio only — no Apex/REST endpoint. The Lightning getSessionId() is deliberately not API-enabled, so the "grab the token and call the Metadata API" path is blocked.

Design confirmed: the LWC assigns permissions; the attendee builds the agent in Agent Studio (guided by the web app). That's exactly the decided architecture — the research validated it rather than changing it.

Platform gotcha found & worked around

Deploying a Custom Metadata record with values via the CLI throws an opaque UNKNOWN_EXCEPTION on these orgs.

  • Proven not-our-fault: a value-less skeleton record deploys fine, and the failure reproduces on a brand-new throwaway CMDT type across API versions 60/62/66.
  • Fix: real defaults live in Apex; the override record was moved out of the deploy path to docs/optional-metadata/ — so a full-source deploy / package build never breaks.
